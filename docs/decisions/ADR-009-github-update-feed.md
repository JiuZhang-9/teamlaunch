# ADR-009: 自动更新源改为「GitHub Releases 为正式源 + 局域网镜像回落」

## Status

Accepted（2026-10-16）｜ 决策人：用户（PM）｜ 实施：架构 ｜ 影响：更新通道、隐私披露、发版纪律

触发记录：`OPEN-DECISIONS.md` D-05 的触发条件 ①（出现局域网外的使用者）与 ②（对外公开分发并要求"下载即能自更新"）已达成——项目已公开（MIT），且"公开下载者拿不到后续更新"是开源体检登记过的 P2 缺口。

## Background

D-05 原决策是"更新源固定为管理员机内嵌服务，暂不切 GitHub"，理由有三：使用者都在同一局域网、切源要求客户端能访问公网、以及"谁在用"会暴露给 GitHub。

现在的事实与变化（2026-10-12 / 10-16 实测）：

- **正式源可行**：`https://github.com/<owner>/<repo>/releases/latest/download/<file>` 可用（302 → 资产 CDN 200）；**支持 Range 请求（返回 206）**，所以差量下载（blockmap）依然生效；实测 3.2 MB/s（≈25 Mbps），117 MB 整包约 36 秒。
- **现状有完整性缺口**：局域网 feed 是**明文 HTTP**（D-02 登记的边界；开源体检登记为 P2"feed 可被 LAN MITM 投毒"）。`latest.yml` 里的 sha512 与安装包走同一条通道，可以被一并替换——自带的校验挡不住网内攻击者。
- **现状有覆盖缺口**：公开下载者与异地办公者没有可用更新通道；管理员机不在网时全公司都收不到更新。
- **反面事实（避免误判为"修坏的东西"）**：2026-10-12 晚局域网源**确实**跑通了一次 1.0.18 → 1.0.20 的自动更新（`%LOCALAPPDATA%\teamlaunch-updater\installer.exe` 与构建产物 sha256 逐字节一致）。本次不是修故障，而是把更新通道扩到公网。

## Decision

**GitHub Releases 为正式源（版本权威），管理员机 feed 降级为"局域网镜像"（加速 + 回落）。**

选源规则（`src/main/updater.ts` → `runCheck`）：

1. 两个源各探一次 `latest.yml`；都探不到 → 本轮静默跳过（源不可达是常态，不是故障）；
2. 谁报的版本新听谁的；**同为最新时优先局域网镜像**（内网快、不占公司出口带宽）；
3. **镜像里没有该版本时回落 GitHub**——这条是必需的：否则"管理员忘了把新版放进分发目录"会把全公司永久钉在旧版本上，而这个故障在界面上与"世界上还没有新版"完全同形，没有人会去查。

实现要点：

- 用 **generic provider 指向 `releases/latest/download/`**，而不是 electron-updater 自带的 github provider。后者要查 `api.github.com`——该域名在部分企业网络不可达，且未认证请求有每小时 60 次限流；直取资产 CDN 两个问题都没有（实测见上）。
- **每个 Release 必须挂 `latest.yml`**（+ 安装包 + blockmap）。没挂＝所有人看不到新版，且失败是静默的。由 `scripts/release-gh.mjs` 一步挂齐并校验。
- 版本比较落在 `src/shared/version.ts`（纯函数，进 smoke）。它只用于**选源**；"要不要更新"的判定权仍在 electron-updater（界面上的"发现新版 / 已就绪"全部来自它的回调），避免出现"状态行说有新版、更新器却不动"的分裂。

## Consequences

**得到**：

- 更新包改走 HTTPS 直取 GitHub CDN，"明文 feed 可被 MITM 投毒"这条在**更新通道**上消失（同步通道仍是局域网明文，那条边界不变）。
- 公开下载者、异地办公者、管理员机不在网的场合都能收到更新（D-05 触发条件 ①②)。
- 管理员机 feed 从"单点依赖"降级为"加速器"：它没在网、或忘了放文件，员工照样能更新。

**代价（明知并接受）**：

- 员工机会规律性访问 `github.com` / `githubusercontent.com`：这是本项目**更新链路的**外网访问点。它不属于遥测（§16.2 的"第三方外网域名 0 条"约束的是埋点出站），但必须如实披露（本次已写入 `SECURITY.md` 与 PRD §15.3.3；首次隐私说明是否加一句、以及是否加"不自动检查更新"开关，见 O-07）。
  **2026-10-17 追加**：新建网页入口时的"取网页标题"成为**第二个外网访问点**（只访问用户正在添加的那个地址、超时 5 秒、只读 64KB、失败静默回落域名），已同步写入 `SECURITY.md` 与 PRD §15.3.3；两处都不计入遥测红线，但对外说明里必须一并披露。
- 更新链路依赖公网可达性。公司网若封 GitHub，员工端会自动改用局域网镜像——这正是镜像必须保留的原因。
- 发版纪律升级为硬依赖：**每版必须挂 `latest.yml`**，由 `npm run release:gh` 保证。
- **过渡**：换源版本（1.0.21）自身只能靠旧通道（局域网 feed）或手动安装送达一次，之后才彻底自由。

**不变**：

- 团队入口配置的同步仍完全走局域网，不受本决策影响。
- 安装包仍未做代码签名（D-01 不变）。更新包由 HTTPS + `latest.yml` 的 sha512 保护，但首次安装仍会触发 SmartScreen 提示。

## 验证方式

- **本机（可访问 GitHub）**：装 1.0.21 后，设置·关于页「检查更新」应显示"已是最新版本 · 来源 GitHub"；把下一个版本发到 Release 后应自动发现、后台下载、弹出常驻横幅。
- **公司内网（员工机）**：GitHub 可达时，镜像与 GitHub 为同一版本 → 状态行应显示"来源 局域网镜像"；GitHub 不可达时应仍能从镜像收到更新。
- 排障证据统一在 `%APPDATA%\TeamLaunch\logs\main.log` 的 `[TL-UPD]` 行（选源、探测结果、下载、安装）。
