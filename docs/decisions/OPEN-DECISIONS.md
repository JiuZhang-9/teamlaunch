### D-04 TypeScript 7.0.2 回退

| 项 | 内容 |
|---|---|

| 重新评估条件 | `typescript-eslint` 发布支持 TS 7 的主版本，且 electron-vite / Vite 8 / Tailwind 4 均无报错时，再评估是否前移 |

## 2. 待裁定事项（Open，需 PM 或相关方拍板）

### O-01 手动刷新与后台轮询对"无变化"的处理不一致

| 项 | 内容 |
|---|---|
| 状态 | **Open**（待 PM） |
| 冲突 | AC-18 要求"刷新结果可感知"（含"无变化"），AC-09 要求"无变化不重绘、不显示干扰性提示" |
| 架构默认实现 | **手动刷新无论结果如何都给反馈；后台轮询无变化时完全静默**。同一结果因触发方式不同而表现不同 |
| 为何必须裁定 | 开发若误以为 AC-09 覆盖一切，会把手动刷新也做成静默，用户点击后无任何反应 |
| 已登记处 | `ARCHITECTURE.md` T3.4、T3.6 不变式 3 |

### O-02 反馈队列超限转 `DROPPED` 时的"可重试动作"语义

| 项 | 内容 |
|---|---|
| 状态 | **Open**（待 PM） |
| 两种实现 | (a) 文案引导：放弃该条，引导改用其他反馈方式（无新页面）(b) 给用户"管理待发送队列"入口，清掉旧的腾位置（**需新增页面，MVP 目前没有**） |
| 架构默认实现 | 按 (a) 实现，不新增队列管理页；试点中若真出现超队列再评估 |

### O-03 零记录对首次事件指标的影响

| 项 | 内容 |
|---|---|
| 状态 | **Open**（待 PM） |
| 背景 | 隐私说明未确认前零记录（禁止预缓冲）。`sign_up_complete` / `first_core_action` 是一次性首次事件，确认前发生的会被永久丢弃且不补发 |
| 后果 | 激活漏斗分母变小，且**无任何报错**——数据看起来正常，只是起点偏少，易被误读为"激活率低" |
| 两个方案 | (a) 接受丢失：激活指标只统计"确认说明后"的用户，口径明确但分母变小(b) 确认后重定义首次：把"确认之后的第一次成功打开"记为 `first_core_action`，语义略变但样本完整 |
| 架构默认实现 | 裁定前按 (a) 走 |
