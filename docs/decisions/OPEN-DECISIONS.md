### O-07 更新检查的隐私披露与开关（ADR-009 的遗留项）

| 项 | 内容 |
|---|---|
| 状态 | **Closed —— ①②都已落地（2026-10-18 用户拍板，v1.0.33）** |
| 背景 | 1.0.21 起更新检查会访问 `github.com` / `githubusercontent.com`——本项目常态化的第三方外网出口。已如实写入 `SECURITY.md` 与 PRD §15.3.3；**首次隐私说明（PrivacyGate）当时没提这一条**（那段文案按 PRD §15.3.1 的三条要求写，改它等于改 PM 定的规则，故未擅动，登记待裁定） |
| ① 披露句 | **已加入**（用户原话："加一句'定期访问，供用户检查更新'"）。落点＝ PrivacyGate 第二段小字，位置在"数据保存在管理员电脑上，不经过外部服务器"之后——否则那句话会被读成"应用完全不连外网"。文案：「另外，应用会定期访问 GitHub 检查是否有新版本（用于自动更新）；不携带设备标识，也与上面这些使用数据无关。不需要的话，可在「设置 · 关于」里关掉自动检查。」 |
| ② 开关 | **已实施（v1.0.31）**：设置项 `autoCheckUpdates`（默认 **true**，保持现状行为），落点在 设置 · 关于页（紧挨更新状态行与「检查更新」按钮）。关掉后**不排任何定时检查**（启动检查与每 6 小时的周期检查都停）＝该机器零自动外网请求；「检查更新」按钮**不受它限制**——那是用户的显式动作，不叫"自动检查"。实现上把原先的 `setTimeout + setInterval` 换成自续期排程（关掉即刻停，不留等死的定时器；也避免"下载比间隔还久"时叠轮次）；状态行在关闭时如实写"自动检查已关闭"，不冒充"已是最新" |
| 验证 | 门禁新增默认值断言（`autoCheckUpdates` 必须默认 true：不能被默认值悄悄关掉）；状态文案优先级进 smoke；打包产物自验——见 CHANGELOG 1.0.31 / 1.0.33 |
