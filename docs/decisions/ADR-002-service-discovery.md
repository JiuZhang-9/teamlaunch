# ADR-002: 局域网服务发现方案

## Status

Accepted（2026-09-29）｜ 决策人：高见远 ｜ 影响：员工端可用性、Windows 防火墙策略

## Background

同步服务内嵌在管理员客户端内，**管理员机器的 IP 由 DHCP 分配，可能变化**。员工端必须在没有人工配置的前提下找到它。这是本项目技术风险最高的一项：找不到服务 = 产品完全不可用。

候选方案：固定配置地址 / mDNS / UDP 广播探测 / 网段扫描 / 上次成功端点缓存。

产品硬约束（来自 PRD）："试点管理员能独立完成，不依赖命令行"、员工首次可用不要求个人配置。任何要求**员工机器**做系统配置的方案都不可用。

## Decision

**采用阶梯式发现（L0→L3），主发现手段为"UDP 广播探测 + 单播应答"（UDP 17891）。明确否决 mDNS。**

```
L0 手动覆盖      settings.serviceUrl          1500 ms   → 迁移到独立服务器的开关
L1 上次成功端点   discovery.json(≤3)          1500 ms/个 → 常规快速路径
L2 UDP 广播探测   255.255.255.255:17891        2500 ms   → 主发现手段（与 L1 并行）
                 + 各网卡定向广播地址
L3 网段 TCP 扫描  /24 + TCP 17890..17899       4000 ms   → 末位兜底，限频 5 分钟 1 次
    ↓ 全部失败
离线模式（ADR-003 的缓存降级）
```

### 为什么选"广播 + 单播应答"

方向选择是关键：**员工端主动发、管理员被动答**。Windows 防火墙对自己发出的 UDP 的应答做状态放行，因此员工机**完全不需要任何入站规则**；只有管理员机需要一条 UDP 17891 入站规则（由提权安装器创建，见 ADR-004）。

若反向设计（管理员定期广播、员工监听），则**每台员工机都需要一条入站规则**，产品前提直接崩塌。

### 为什么否决 mDNS / bonjour-service（决定性理由）

1. **它需要员工机器开放 UDP 5353 入站。** mDNS 的应答以组播形式回到 `224.0.0.251:5353`。Windows Defender 防火墙默认拦截未经授权进程的入站 UDP，未放行的机器表现为"查询发出但收不到任何回包"。纯 JS 实现（bonjour / bonjour-service）在 Windows 上因此频繁失效。要给每台员工机的 Node/Electron 可执行文件开 5353 入站，与"员工零配置"直接冲突。
2. **端口 5353 冲突。** 已安装的 Bonjour 服务（iTunes / iCloud / Adobe 套件）占用 5353，导致 `EADDRINUSE`，连"先申请先占"都做不到。
3. **企业网络常禁用组播。** 办公 Wi-Fi 普遍开启 AP 隔离，组播跨不了 AP，且失效是完全静默的，排查成本极高。

### 为什么不完全依赖网段扫描

254 次 SYN 在严格网络里会触发安全软件/EDR 告警。因此它只作为 L3 末位手段：UI 明示"正在扫描局域网"、限频每 5 分钟 1 次、结果一经确认立即回写 L1 缓存避免重复。

### 报文格式

```
查询（员工 → 广播）：
{ "magic":"TLDISCOVER1", "type":"query", "nonce":"<16B hex>", "anonDeviceId":"<匿名设备 ID>" }

应答（管理员 → 员工源地址单播）：
{ "magic":"TLDISCOVER1", "type":"offer", "nonce":"<回显>",
  "serviceId":"<安装实例 UUID>", "instanceId":"<团队数据源 UUID>",
  "name":"ADMIN-PC01", "httpPort":17890, "revision":128, "addrs":["192.168.1.10"] }
```

- `magic` 为协议版本哨兵，不匹配即丢弃，将来可平滑换协议。
- `nonce` 回显用于丢弃迟到/重复的应答。
- **`httpPort` 必须广播真实端口**：端口可能因占用而在 17890–17899 间漂移（ADR-004），写死会导致发现成功但连不上。
- `instanceId` 用于识别"数据源换了实例"，避免员工接到另一个团队的数据。

## Consequences

**正面**
- 员工端零配置：不需要任何防火墙规则、不需要知道管理员 IP、不需要改本机网络配置文件。
- 天然抗 DHCP 变更：IP 变了 L1 失败，L2/L3 兜底并回写新端点。
- 实现量小（约 150 行），无第三方依赖，无原生模块。
- 只有一条 UDP 端口规则，且由提权安装器创建，程序员和用户都不必手工操作。

**负面与代价**
- 广播不跨子网。跨 VLAN / 跨 VPN 的场景不可发现 —— 这已在 PRD §10 中明确排除（"互联网远程访问"、"跨网络 SSO"均不做），因此可接受。
- 若某台机器的活动网络配置文件是 Public，Windows 仍可能拦掉 UDP。诊断项 ADR-004 负责暴露。
- L3 扫描在某些企业环境可能需要由设置手动关闭；已提供开关。
