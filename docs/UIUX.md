## 0. 三轴刻度与为什么是这个值

| 维度 | 取值 | 本项目的理由 |
|---|---|---|
| DESIGN_VARIANCE | 5（偏移） | 卡片墙必须可"一秒扫视"，所以网格本身严格对称规则；非对称只体现在三处：工具栏左对齐标题、搜索框右对齐、空状态/错误态左对齐。>4 已强制禁用居中 Hero，本项目首屏就是卡片，天然满足。 |
| MOTION_INTENSITY | 4（克制） | 这是每天被调用几十次的高频工具窗口，"流畅"= 快、可预期、不打断，不是"有动画"。所有交互 ≤240ms，无待机微动画（唯一例外：离线状态点的呼吸，见 5.4）。 |
| VISUAL_DENSITY | 6（日常偏紧） | 一屏 24 张卡片（6 列 × 4 行）是可用性与密度的平衡点。不进入驾驶舱模式（无 border-top 分组、无等宽数字墙），因为主要用户是非技术员工（PRD 画像 B / C）。 |

## 1. 设计方向

### 1.1 产品寄存器判断

**Product 寄存器（设计服务产品，不是设计本身）**。TeamLaunch 是管理后台/工具 UI 类型，不是营销落地页。因此：
- 色彩走**克制策略**：着色中性色 + 单一强调色，强调色可见占比目标 ≤8%
- 排版禁止衬线体做标题；允许 serif 仅作为远期品牌延展，本版不用
- 动效只做功能性动效（状态反馈、空间连续性），无装饰性动画
- 不用照片/插画，用图标、真实应用图标、数据（路径/域名/时间）承担视觉重量

### 1.2 对标品牌

| 对标 | 借用什么 | 明确不借什么 |
|---|---|---|
| **Raycast（主对标）** | 键盘优先的血统：统一结果行结构、`Alt+数字`直达、输入框即筛选器、快速唤起的"预热 + 瞬时显示"手感；以及"深色、紧凑、信息密度高但零装饰"的整体气质。 | 不借它的插件/扩展 store 观感（卡片 grid + 花哨封面），也不借 'confetti' 类愉悦动效——本项目是内网工具，克制优先。 |
| **Linear（视觉工艺）** | 工艺标准：1px 描边、几乎不用阴影、层级靠表面亮度而非投影；字重只用 3 级；状态色低饱和；hover 反馈 <160ms。这是我方"精致感"的主要来源。 | 不抄袭它的紫色系（本项目禁用紫粉系），也不借它的 projects/issues 结构。 |
| **Windows 11 Fluent（平台贴合）** | 圆角 8px 的控件语言、窗口标题栏行为、`Segoe UI Variable` 的 UI 字重节奏、消息条/Toast 的位置。 | **不用 Acrylic/Mica 毛玻璃**（装饰性模糊是禁止项，且在 Electron 上极易产生廉价感与性能问题）；不用 Segoe Fluent 花体图标。 |

一句话结论：**用 Raycast 的手感 + Linear 的工艺 + Windows 11 的平台贴合，做一张"敢给行政同事看、敢给设计师看"的卡片墙。**

### 1.3 三个可选方向（供决策感知差异）

| | 方向 A：石墨工具台（推荐） | 方向 B：温润工作台 | 方向 C：专业控制台 |
|---|---|---|---|
| 氛围关键词 | 冷静、精准、克制 | 亲切、轻盈、好接近 | 权威、密集、运维感 |
| 默认主题 | 深色 | 浅色 | 深色（更冷更黑） |
| 主色 | 电光青蓝 `#106696` / 深色 `#3890CE` | 陶土橙 `#B4471F` / 深色 `#E08556`（仅方向 B 启用，见 §2.3 备选） | 钢蓝 `#1F4E79` + 琥珀状态色 |
| 中性色 | 石墨冷灰（`#14171A` 系） | 明亮冷白（`#F7F8FA` 系，不用米色奶油） | 纯石墨黑（`#0E1114` 系） |
| 圆角 | 卡片 12 / 控件 8 | 卡片 14 / 控件 10 | 卡片 8 / 控件 6 |
| 密度 | 6 | 4 | 8（默认列表视图） |
| 适合团队 | 技术/产品/设计混合（10–50 人） | 行政/财务/销售占比高 | IT 运维、入口数 >150 |
| 优点 | 最耐看、第三方彩色应用图标在深灰底上最清晰、夜间友好 | 非技术员工上手门槛最低 | 单位面积信息量最大 |
| 风险 | 需要更强的对比度控制 | 长时间使用不够沉稳；暖色调易显"消费级" | 对 20 张卡片的小团队显得空旷且冷硬 |

**推荐方向 A，理由三条：**
1. **对话收集到的最高频诉求是"不要又土又乱"**——深色 + 单一冷调强调色 + 统一描边图标给的真实感最强，也最容易掩饰第三方应用图标分辨率不齐的事实（低清 exe 图标在深灰容器里比在白底上体面得多）。
2. **启动器是短时高频窗口**，一天可能弹出 30 次。深色窗口在浅色桌面上有清晰的边界，视觉切换成本更低，也不容易被误认为"又一个白后台"。
3. **方向 C 的密度优势在 MVP 不成立**：PRD 假设实际高频入口 ≤60 个，不必为 200 卡片优化；方向 C 作为"列表视图"在 P1 提供即可（见 §3.11 备选视图）。

### 1.4 主题默认值结论

- 出厂设置：**主题 = 跟随系统（`system`）**
- 系统主题读取失败或未启用深色模式时的兜底：**深色**
- 若必须二选一：**深色**
- 设置项必须提供三态切换（浅色 / 深色 / 跟随系统），切换即时生效、**不重绘卡片数据**、不打断当前搜索或滚动位置。

## 2. Design Token 体系

### 2.1 分层与命名规范

```
A1-identity    → 品牌核心：主色 / 中性色 / 字体 / 窗口尺寸        （不可省略）
A1-structure   → 字号阶梯 / 网格 / 节区节奏 / 容器宽度            （不可省略）
A2-semantic    → 语义色（success/warn/danger/info）/ 动效时长      （有默认值，必须声明）
B-slot         → 组件别名：--surface-2 / --fg-2 / --meta          （必须声明）
C-extension    → 本项目专属：入口类型 tint / 编辑态表面 / 状态条    （自由扩展）
```

命名规则：`--{类别}-{角色}[-{变体}][-{状态}]`，**按用途命名而非按色相命名**（不允许出现 `--blue-500` 这种名字出现在组件样式里）。
所有颜色值只能以 `--` 变量形式出现在组件代码中；唯一允许的字面量是 `#fff` 与 `#000`（且本项目实际未使用）。

### 2.7 字体方案

```css
--font-sans: "Inter Variable", "Inter", system-ui, -apple-system, "Segoe UI Variable Text", "Segoe UI", "Microsoft YaHei UI", "Microsoft YaHei", sans-serif;
--font-cjk:  "Noto Sans SC", "Source Han Sans SC", "HarmonyOS Sans SC", "MiSans", "Microsoft YaHei UI", "Microsoft YaHei", sans-serif;
--font-body: var(--font-sans), var(--font-cjk);
--font-mono: "JetBrains Mono", "Cascadia Mono", Consolas, monospace;
```

**决策说明（桌面端与 Web 的关键差异）**

| 项 | 结论 | 理由 |
|---|---|---|
| 西文 UI 字体 | **Inter Variable（打包 latin 子集，约 250–320KB woff2）** | 它是 UI 场景的通用解，不作为"展示字体声称高级"（那才是字体 monoculture 陷阱）。字重精确到 400/510/590 需要可变字体；若改用静态实例则回落到 400/500/600。 |
| 中文字体 | **打包 Noto Sans SC（SIL OFL，仅 400 + 510 两个字重，GB2312 常用字子集约 3–4MB）** | 这是本地安装的 Electron 应用，不是网页，多出 3–4MB 不产生加载成本；而"设计感"有一半来自中文不是微软雅黑的粗重笔画。思源黑体 / Noto Sans SC 是当前中文 UI 的开源黄金标准（7 种字重、字面大、小字号可读性极佳），授权允许随应用分发。系统字体放在 `--font-cjk` 尾部作为兜底。 |
| 不打包的字 | Opt-out：若最终安装包体积受限，允许改为"仅打包 Inter + 中文走系统微软雅黑 UI"，此时需把卡片副标签字号从 12px 提到 13px，并接受"观感下降一档"。该决策需在 Spec 中显式记录。 | — |
| 等宽字体 | JetBrains Mono（打包基础子集，约 150KB） | 仅用于版本号、路径片段、诊断信息（可复制的技术信息）。Windows 10 上回退到 Cascadia Mono / Consolas。 |
| 数字 | `font-feature-settings: "tnum" 1, "cv05" 1` 应用于版本号、时间、计数 | 表格/列表中的数字对齐是"专业感"的低成本来源。 |

**字重三级体系（不允许第四级）**

| 级别 | 值 | 用途 |
|---|---|---|
| Read | 400 | 正文、卡片副标签、说明 |
| Emphasize | 510 | 卡片标题、Tab 文字、按钮文字、分组标题 |
| Announce | 590 | 对话框标题、空状态主标题、版本号强调 |

### 2.8 字号阶梯（A1-structure）

单位 px，Windows 用户默认 DPI 100%；125%/150% 缩放下由 Electron + 系统处理，禁止用 transform: scale 自己缩放。

| Token | 字号 / 行高 | 字距 | 用途 |
|---|---|---|---|
| `--text-2xs` | 11 / 16 | 0.01em | 徽标文字、计数角标 |
| `--text-xs` | 12 / 18 | 0.01em | 时间戳、路径副标签、类型标签 |
| `--text-sm` | 13 / 20 | 0 | 卡片标题、列表正文、表单标签、按钮（小） |
| `--text-base` | 14 / 22 | 0 | 默认正文、搜索输入框、菜单项、卡片标题（编辑态） |
| `--text-md` | 15 / 22 | 0 | 分组标题、Toast 正文 |
| `--text-lg` | 17 / 26 | -0.01em | 对话框标题、页面标题（工具栏） |

## 3. 界面布局方案

### 3.1 窗口尺寸推导（为什么是 1040 × 720）

```
1040 (窗宽)
 - 24 × 2 (左右内边距)        = 992  内容可用宽度
  992 = 6 × 152 + 5 × 16     → 恰整除为 6 列，列宽 152

720 (窗高)
 - 40 (标题栏)                = 680
 - 56 (工具栏)                = 624
 - 24 × 2 (上下内边距)        = 576  内容可用高度
  576 = 4 × 132 + 3 × 16     → 恰整除为 4 行
```

结论：**默认窗口下，一屏正好 6 列 × 4 行 = 24 张卡片，零滚动条、零半行截断。**

选择依据：
- 测试横向：办公室最常见的 1366×768（减任务栏约 728 可用）能完整容纳 720 高度；1920×1080 下窗口仅占屏约 48%，不压迫桌面。
- 4 行 24 张对应 PRD §5.1「建议每组 24 张卡片」——一个分组在一屏内能看完。
- 704px 最小宽度 = 4 列，保证笔记本竖屏或分屏（Windows 贴靠 50%）仍可用。

**缩放行为**：844 / 1040 / 1208 / 1376 宽度分别对应 5 / 6 / 7 / 8 列并同样整除（列宽 152）。建议在窗口 resize 结束时对宽度做 ±8px 内吸附到这些值，让网格永远整齐——这是"花了心思"的细节。

**滚动条硬约束**：默认尺寸下网格宽度是精确整除的，**任何占布局宽度的滚动条都会让列数从 6 掉到 5**。因此：
1. 主窗口必须使用 overlay 滚动条（`scrollbar-width: thin` + WebKit `::-webkit-scrollbar { width: 0 }` 或 Electron 的 overlay 设flags）
2. 或统一预留 `scrollbar-gutter: stable`（12px），并把内容宽度按 980 重算列数 = 5

推荐方案 1（overlay），深色主题下自定义 track/thumb：`thumb = var(--border-strong)`，`track = transparent`。

### 3.2.1 同步状态指示器（8 态，硬性）

**禁止用布尔"在线 / 离线"表达同步状态。** 状态机落地为 **8 态**，与 PRD §5.4.1 / 架构 v1.4（T3.6 / T3.6.1）对齐。
比 v1.2 多出的第 8 态是 `SYNC_DATA_REJECTED`——「返回数据校验失败」被架构明确为**独立状态而非离线原因**，因为那一刻服务是连通的。指示器位于工具栏 Tab 右侧，结构固定为「状态点（10px）+ 图标（16px）+ 文案（12px `--fg-2`）」，三项缺一不可。

| # | 枚举名 | 中文 | 触发条件 | 状态点 | 图标 | 文案 | Banner / 页面 |
|---|---|---|---|---|---|---|---|
| 1 | `NEVER_SYNCED` | 首次未同步 | 本机从未成功拉取过团队数据 | 空心（1px `--border-strong` 描边，无填充） | `cloud-off` | `尚未获取团队入口` | 不显示 Banner，走 §4.2 空状态 |
| 2 | `SYNCING` | 正在同步 | 启动拉取 / 手动刷新 / 本轮轮询进行中 | `--info-solid` + `loader-circle` 旋转（1200ms linear） | `loader-circle` | `正在同步…` | 不显示 |
| 3 | `ONLINE_LATEST` | 在线且已最新 | **本轮**轮询成功且版本一致 | 实心 `--success-solid` | `cloud` | `已同步 · 今天 09:12` | 不显示 |
| 4 | `ONLINE_UPDATE_PENDING` | 在线有待应用更新 | 本轮轮询发现新版本，正在替换 | `--info-solid` + `loader-circle` 旋转（1200ms linear） | `loader-circle` | `正在应用更新 v27…` | 应用完成后显示 info 条，4s 后自动收起 |
| 5 | `OFFLINE_CACHED` | 离线有缓存（`hasCache=true`） | 服务不可达，本机有上一次成功数据 | 半亮 `--warn-solid` + 2400ms 呼吸 | `cloud-off` | `离线 · 数据时间 今天 09:12` | warn 条 + 「重试」；**照常展示缓存卡片** |
| 6 | `OFFLINE_EMPTY` | 离线无缓存（`hasCache=false`） | 服务不可达且本机无可用数据 | 实心 `--warn-solid` | `cloud-off` | `暂时无法获取团队入口` | warn 条（两行：状态行 + 原因行）；**页面走 §4.2 离线空状态** |
| 7 | `SYNC_DATA_REJECTED` | 在线但数据被拒 | **拿到响应**但三重校验失败，已保留旧缓存（PRD §13 数据损坏） | 实心 `--warn-solid` + 2400ms 呼吸 | `triangle-alert` | `更新未完成 · 仍使用今天 09:12 的数据` | warn 条（两行）；**照常展示缓存卡片** |
| 8 | `SYNC_FAILED_UNKNOWN` | 同步失败 / 未知 | 本轮轮询未成功完成（超时、返回损坏、原因未知） | 实心 `--warn-solid` | `circle-x` | `同步未完成 · 数据时间 今天 09:12` | warn 条 + 「重试」「查看诊断」 |

**五条不可违反的规则**

1. **状态只能由同步服务写入，UI 不得自行推导。** UI 只做「枚举 → 视觉」的映射：不得因为 fetch 抛错就自己判定为离线，不得用本地时钟判断版本先后，不得沿用上一轮状态。状态值变化时 UI 才重画。
2. **"已同步"只在当前轮询周期内有效。** 下一轮没有成功完成，必须退到 `SYNC_FAILED_UNKNOWN`，**严禁沿用上一轮的 `ONLINE_LATEST`**。文案里的"数据时间"必须是最近一次成功同步的时间戳，不得随时间流逝滚动刷新。
3. **`OFFLINE_CACHED` 与 `OFFLINE_EMPTY` 是两套完全不同的行为，不能共用一种空态。**
   - `OFFLINE_CACHED`：卡片墙照常渲染缓存内容，卡片可点击，顶部 warn 条说明数据时间 + 「重试」。
   - `OFFLINE_EMPTY`：不渲染任何团队卡片，走 §4.2 的离线空状态页（主标题 `暂时无法获取团队入口` + 原因行 + 「重试刷新」+「去看看我的入口」）。**主标题只说员工能懂的状态语义，具体原因交给第二行**——不要用「未找到同步服务」做主标题，员工容易把"服务"理解成"公司停了这个功能"。
   - `hasCache` 由同步服务写入，UI 不得自己猜（例如不得"卡片数为 0 就当没缓存"）。
4. **故障原因走「状态 + 原因」两段式，不扁平进枚举。** 主文案由状态枚举决定，补充文案由同步服务写入的 `offlineReason` 决定（见下表）。UI 只做映射，**不自行判断网络**，也**不得把原始错误码或英文原因直接显示给员工**。
5. **非颜色通道必须齐全**：8 态用四种点形态（空心 / 实心 / 旋转 / 呼吸）+ 6 个不同图标 + 各自文案区分。灰度化后仍能区分。轮询成功且版本一致时（`ONLINE_LATEST` → `ONLINE_LATEST`）**零重绘、零闪烁、卡片网格零变动**（PRD AC-09）。

6. **「数据被拒」是状态不是原因。** `SYNC_DATA_REJECTED` 那一刻服务是连通的，只是服务端拒了脏数据、保留了旧缓存。归入离线语义会让用户看到"网络不可达"而实际上网是好的——这是误导。文案按**状态键**取，不要按原因键取。

**`offlineReason` 映射表（键名已对齐架构 v1.4 T3.6.1，按真实频率降序）**

文案结构固定为两行，由 PRD §5.4.1.1 固化：

- **第一行（状态行）**：由状态枚举决定，说员工能懂的状态语义。
- **第二行（原因行）**：由 `offlineReason` 决定，**必须自带下一步动作**（稍后自动重试 / 手动刷新 / 使用我的入口 / 联系管理员或 IT）。

| 序 | `offlineReason`（架构正式枚举） | 第二行原因文案（12px） | 内嵌的下一步动作 | 附带操作按钮 | 频率 |
|---|---|---|---|---|---|
| 1 | `SERVICE_NOT_FOUND` | `管理员电脑未开机或未连接网络。稍后会自动重试，你也可以手动刷新。` | 稍后自动重试 / 手动刷新 | 「重试」 | **高频** |
| 2 | `NETWORK_UNREACHABLE` | `这台电脑连不上内网。检查网络后会自动重试，你也可以手动刷新。` | 检查网络 / 手动刷新 | 「重试」「查看诊断」 | 中 |
| 3 | `UNKNOWN`（兜底） | `暂时连不上管理员电脑，稍后会自动重试。你也可以先使用我的入口。` | 稍后自动重试 / 使用我的入口 | 「重试」「去看看我的入口」 | 兜底 |
| 4 | `CONNECTION_BLOCKED` | `连接被安全软件或网络策略拦截。可手动刷新，仍不行请联系管理员或 IT。` | 手动刷新 / 联系管理员或 IT | 「重试」「查看诊断」 | **罕见** |

**视觉权重纪律**：四行的视觉处理**完全相同**（都是第二行 11px），频率排序只用于两件事——
① 不得给罕见的 `CONNECTION_BLOCKED` 加事故级样式（它只在"信标 UDP 通而 TCP 不通"这一窄条件下成立，写得像事故会把注意力引到"是不是被监控了"）；
② 不得把最高频的 `SERVICE_NOT_FOUND` 写得比兜底还轻（管理员关机、服务没起都落这里，必须给足下一步动作）。
**技术上无法区分的情况不许硬编文案**：`NETWORK_UNREACHABLE` 无法区分"管理员关机"与"中间件拦截"，这一支只说本机侧网络状态，不许猜成"管理员关机了"。

> 原「返回数据校验失败」一行已从本表移出，改为状态 `SYNC_DATA_REJECTED`（见上方状态表第 7 行）。

> 兜底规则：**未覆盖的原因码一律回退到「未知」那一行**，禁止暴露原始错误码、堆栈、英文原因、服务端地址与端口。诊断详情只在「查看诊断」里以可复制文本提供（PRD §13）。
> **主标题不得用「未找到同步服务」**——它是原因不是状态，员工容易把"服务"理解成"公司停了这个功能"。主标题只用「暂时无法获取团队入口」这类状态语义。

1. **只有两个一级页面**（PRD §5.5 已定并列 Tab）。此时左侧栏要吃掉 180–220px 横向成本，换来的只是两个文字项；底部栏要吃掉 56px 纵向成本并挡住第 4 行卡片。**任何一种都比顶部 Tab 少两张卡片。**

### 3.6 三类入口：如何既统一又区分（三层区分）

**统一层（100% 共用）**：卡片尺寸、圆角、描边、内边距、标题字号/字重、点击行为、hover 抬起、键盘可聚焦、更多菜单位置。

**区分层一：图标（默认可见，最强信号）**

| 类型 | 图标来源优先级 | 规格 |
|---|---|---|
| 软件 | 1. 本机 `app.getFileIcon(p, {size:'large'})`（Windows 上限 32×32）→ 2. 管理员发布时附带的高清图标 → 3. Lucide `AppWindow` 回退 | 真实图标按原生尺寸渲染，**最大铺满 32×32，圆角 6px**；回退图标 24px 居中，容器底 `--type-app-container` |
| 文件夹 | **统一使用 Lucide `Folder`**（不用系统文件夹图标，跨主题/跨 Windows 版本不一致） | 24px 居中，容器底 `--type-folder-tint`，圆角 8px |
| 网页 | 1. 管理员端抓取并随发布版本同步下发的 favicon（员工端**不联网取**）→ 2. Lucide `Globe` 回退 | favicon 24×24 居中（不做圆角，保持站点方形识别）；回退用 24px 描边图标 + `--type-link-tint` 底 |

**平台限制（架构已核实，设计据此定稿）**

- **本地软件图标在 Windows 上的物理上限是 32×32**：Electron `app.getFileIcon(size:'large')` 在 Windows 走 `SHGetFileInfo`，返回值就是 32×32（48×48 只在 Linux 上成立）。因此卡片 / 搜索结果里的软件图标**按 32 逻辑像素出稿**，不需要也不能获得 48/64 资源。
  - 处理规则：返回图小于 24px（部分 lnk 只有 16）时**不放大**（放大必糊），改为居中显示在 40×40 容器内，或直接用 Lucide `AppWindow` 回退。
  - 150% 系统缩放下允许显示器做轻微上采样，属系统行为，设计稿不为此出 48px 版本。
  - 这也是为什么"统一容器"工艺对本项目格外重要：把参差不齐的 16–32px 真实图标装进同一个 40×40 / 圆角 8px / 1px 描边的框里，是卡片墙显得设计过的唯一可行手段。
- **网页 favicon 由管理员侧抓取后随版本下发**：员工端渲染时零网络请求，所以不存在"favicon 加载中"的异步等待；若该版本未携带 favicon，直接渲染 `Globe` 回退，不允许出现占位空框或破图。
- **MVP 不提供内置浏览器窗口**：点击网页入口一律交给系统默认浏览器（内置 Chromium 是独立 profile，企业内网 SSO 会失败）。因此**不存在**需要设计的浏览器 chrome / 前进后退 / 地址栏 / 页面加载态；网页入口的"打开成功"判定只到"已交给系统浏览器"为止，浏览器内的业务失败由员工主动反馈（PRD §5.3）。

> 关键工艺：**所有第三方图标（exe 图标、favicon）都套同一个 40×40 / 圆角 8px 的容器 + 1px `--border-subtle` 描边**。这是本项目视觉一致性的核心动作。

**区分层二：副标签的类型化信息（默认可见）**

| 类型 | 副标签默认文案 | 示例 |
|---|---|---|
| 软件 | `桌面应用` 或 `最近使用 · 3 天前` | `桌面应用` |
| 文件夹 | 路径末级（盘符保留，中间截断） | `D:\共享\2026 归档` |
| 网页 | 域名（去 www / 去协议） | `git.internal.company.com` |

**区分层三：类型角标 + 类型文字（hover / 列表视图 / 搜索结果 / 编辑态）**

- 卡片右下角 12px 类型角标图标：`AppWindow` / `Folder` / `Globe`（统一 Lucide 描边风格，角标允许 stroke-width 1.75，见 §6）
- 编辑器：三选一类型选择器，每项是「24px 图标 + 类型文字 + 一句说明」
- 搜索结果行：**始终**显示 12px 类型文字标签（`软件` / `文件夹` / `网页`）

**为什么不给三类上三种鲜艳底色**：①三色会让 24 张卡片变成配色噪音，直接毁掉"简洁"；②色觉障碍用户无法区分（`--type-folder-tint` 与 `--type-link-tint` 明度接近）；③应用真实图标自带颜色，容器再上色必然打架。因此**色只给两类**（文件夹、网页），软件走中性容器。

**硬性规则**
1. 未作出选择前，**不得上报任何事件**，也不得把事件写入本机缓冲等确认后补发。"先缓冲"本质已经把行为写进本机文件，一旦实现走样或用户长期不确认，就变成事实上的先采集后追认。
   - **最宽松的可接受形态**（PRD 已留档）：**仅内存暂存、确认即写入、关闭即丢弃**——不得落盘、不得跨启动保留。若实现有困难可用这一档，但**持久化缓冲一律不允许**。
2. 必须提供**两个真实可选出口**（允许 / 不允许）。禁止只给一个按钮，禁止只有窗口关闭键这种"假选择"。
3. **不允许做 dismissible Banner**（可被右上角 X 关掉就等于没有门）。
4. 选择结果写入本机配置并持久化；可通过设置随时更改，不再二次弹窗。
5. **文案禁用词**：`云端`、`上云`、`云端分析`、`上传分析`、`ai 优化体验`、`数据资产`。本产品数据不出内网，任何暗示数据出网的表达都是错的。
6. 该页面本身也必须在浅色 / 深色两套主题下各目视一遍；深色下 `--muted` 仍是 5.87:1 达标。

### 3.14.1 设置中的遥测开关

- **位置：设置第一屏，一级可见**，不折叠、不放在二级折叠面板里、不和"高级选项"并列收纳。可用性验收口径：5–8 人测试中 **100% 能在设置里找到并成功关闭**。
- 结构：`label 13px/510 --fg` + `switch 组件` + `副文案 12px --muted`（副文案随开关状态切换）
- 开关态：
  - 开：`--accent` 底，滑块 `--accent-on`；副文案 `正在记录匿名使用数据，可在下方查看记录内容说明`
  - 关：`--border-strong` 描边 + `--bg-surface-2` 底，滑块 `--meta`；副文案 **`关闭后不再记录任何使用数据`**
- 关闭后必须立刻三件事：**停止记录 / 清空本地缓冲 / 不再发起上报请求**。界面文案必须与行为一致——不允许"关了还在传"。
- 开关切换用 160ms `--ease-standard`，切换后副文案淡入 120ms，无位置跳动。

## 4. 状态设计（5 态 + 4 专项）

### 4.1 Loading

**骨架屏，不用 spinner**（PRD §13 要求"不能让卡片反复跳动"）。

- 骨架卡片：尺寸与真实卡片完全一致（152×132），背景 `--bg-surface-2`，圆角 12px
- 内部：40×40 骨架块（圆角 8px）+ 两条 8px 高、宽 70% / 50% 的骨架条（圆角 4px），间距与真实排版一致
- 骨架数量 = 上次可见列数，铺满一屏，**之后不再变化**，即使数据来了也不重排
- Shimmer：`--bg-surface-hover` → `--bg-surface-2` 斜坡，`linear-gradient(90deg, transparent 0%, rgba(255,255,255,0.06) 50%, transparent 100%)`，1200ms linear infinite，背景位置移动
- 超过 300ms 仍未返回（PRD §13 阈值）：Toolbar 状态区从「正在同步…」变为同步指示器 `LoaderCircle` 旋转（800ms/step，`--motion-slow` 不适用——这是常态旋转，用 1.2s linear infinite），仍不换布局
- reduced-motion：静态灰块，无 shimmer，旋转降级为静态 `loader-circle` 图标 + 状态文本「正在同步…」

### 4.2 Empty

| 页面 | 主标题（15px/510） | 说明（13px `--fg-2`） | 主操作 |
|---|---|---|---|
| 团队入口 · 员工 · 已同步无内容 | 团队入口还没有内容 | 管理员发布后，你会在这里看到团队统一的软件和文件夹。 | 「去看看我的入口」（次级） |
| 团队入口 · 员工 · `OFFLINE_EMPTY`（AC-11） | 暂时无法获取团队入口 | 管理员电脑未开机或未连接网络。稍后会自动重试，你也可以使用我的入口。 | 「重试刷新」（主）+「去看看我的入口」（次级） |
| 团队入口 · 管理员编辑态 | 团队入口还没有内容 | 按 Ctrl+N 添加软件、文件夹或网页，发布后全员可见。 | 「添加第一个入口」（主） |
| 我的入口 · 首次 | 这台电脑上还没有个人入口 | 把常用的软件、文件夹和网页加进来，只有你自己能看到。 | 「添加第一个入口」（主） |
| 搜索无结果 | 没有匹配「报销」的入口 | 试试只输入两个关键词，或者切换另一个页面查找。 | 无（给「清空搜索」文字按钮） |

排版规范：视觉块整体**左对齐**于第一列卡片位置，顶部留 `--space-12`（48px）；上方一个 48px 的 `layout-grid` 图标（`--meta` 色，不用 accent——accent 要留给真正立即可执行的动作）；主标题与说明最大宽度 420px。

**`OFFLINE_CACHED` 与 `OFFLINE_EMPTY` 不允许共用空态**
- `OFFLINE_EMPTY`（`hasCache=false`）→ 上表第 2 行的离线空状态页，**不渲染任何团队卡片**。
- `OFFLINE_CACHED`（`hasCache=true`）→ **不出现空状态页**，照常渲染缓存卡片墙，只在顶部 Banner 说明数据时间。即使缓存内容为空（管理员发布了 0 个入口），也应显示"团队入口还没有内容"这类**正常空态**，而不是"离线"空态。
- `hasCache` 由同步服务写入，UI 不得用"卡片数为 0"自行推断。

### 4.3 离线 / 版本提示 Banner

插在工具栏与内容区之间，出现时内容区高度 -40px（用 `--motion-base` 做 height + opacity 展开），不用浮层遮挡卡片。**Banner 是 §3.2.1 八态系统的延伸**，不是独立装饰。

Banner 采用**两段式**：第一行「状态文案」（由状态枚举决定），第二行「原因文案」（由同步服务写入的 `offlineReason` 决定，映射表见 §3.2.1）。两段各自独立，**不把原因扁平进状态枚举**，也不把原因写死在 UI 里。

| 对应状态 | 视觉 | 第一行（状态） | 第二行（原因，来自 `offlineReason`） | 附带操作 |
|---|---|---|---|---|
| `OFFLINE_CACHED` | `--warn-bg` + `cloud-off` 16px `--warn-fg` | 离线 · 数据时间 今天 09:12 · 显示的仍是上次成功同步的入口 | `SERVICE_NOT_FOUND`（高频）：管理员电脑未开机或未连接网络。稍后会自动重试，你也可以手动刷新。 | 「重试」 |
| `OFFLINE_EMPTY` | 同上 | 暂时无法获取团队入口 | 按 `offlineReason` 取（四值映射表见 §3.2.1，示例为 `CONNECTION_BLOCKED`：连接被安全软件或网络策略拦截。可手动刷新，仍不行请联系管理员或 IT。） | 「重试」+「去看看我的入口」 |
| `SYNC_DATA_REJECTED` | `--warn-bg` + `triangle-alert` | 更新未完成 · 仍使用今天 09:12 的数据 | **不走 `offlineReason`**：返回数据校验失败，仍使用上一版本。你可以手动刷新再试。 | 「重试」「查看诊断」 |
| `SYNC_FAILED_UNKNOWN` | `--warn-bg` + `circle-x` | 同步未完成 · 数据时间 今天 09:12 | 按 `offlineReason` 取，未覆盖回落 `UNKNOWN` 兜底行 | 「重试」「查看诊断」 |
| `ONLINE_UPDATE_PENDING` → `ONLINE_LATEST` | `--info-bg` + `refresh-cw`，**4s 后自动收起** | 团队入口已更新至 v27（3 项变更） | 无 | 无（不接受永久性 banner） |

> `SYNC_DATA_REJECTED` 那一行**不读 `offlineReason`**（该字段此时为 `null`）——它是状态语义不是原因语义。把它写成"网络不可达"是误导：那一刻服务是连通的。

规范要求：
- 状态一律走 **图标 + 文字**双通道；不允许仅用颜色表达状态，也不允许把 Banner 做成没有信息的装饰色块。
- Banner 高度固定 40px，同一时间**最多显示 1 条**（优先级：`SYNC_FAILED_UNKNOWN` > `OFFLINE_EMPTY` > `OFFLINE_CACHED` > 更新提示）。
- 「数据时间」必须是最近一次成功同步的时间戳，**不得随时间流逝自动刷新**，也不得在下一轮失败后继续沿用旧文案。
- 员工侧**不显示**服务端地址、端口、错误码、堆栈；这些只在「查看诊断」的可复制文本里（PRD §13）。

### 4.4 Error

| 层级 | 表现 |
|---|---|
| 卡片级（目标在本机失效，AC-12） | Error 态卡片（§3.7）；点击后原地展开一行详情：`triangle-alert` 12px + 「本机未找到该软件」+ 次级按钮「重新定位」「复制诊断」「反馈给管理员」，160ms 展开 |
| 页面级（`SYNC_FAILED_UNKNOWN` / `OFFLINE_CACHED`） | 保留缓存卡片不清除；顶部用 4.3 的两段式 Banner（状态行 + `offlineReason` 原因行） |
| 页面级（`OFFLINE_EMPTY`，`hasCache=false`） | 走 4.2 的离线空状态页（主标题 `暂时无法获取团队入口`），**不显示堆栈、不显示英文错误码、不显示端口**；「查看诊断」可复制一次英文/技术信息（PRD §13 允许复制诊断信息） |
| Toast 级 | `--danger-bg` + `triangle-alert` + 文案 + 「重试」 |

文案示例（真实场景）：
- 「本机未找到该软件：C:\Program Files\审稿工具\review.exe」
- 「文件夹不存在或当前无权限：D:\旧盘\2024 归档」
- 「链接格式无效：htp:/ git.internal.company.com」
- 「暂时无法获取团队入口，当前显示的是上一次成功同步的内容」（**员工可见文案不含地址与端口**；`192.168.1.24:5577` 这类信息只出现在「查看诊断」的可复制文本里）

### 4.5 Success / Edge

- Success：Toast，底部居中偏右（距右 `--space-6`、距底 `--space-6`），40px 高，`--success-bg` + `circle-check` 16px + 13px `--success-fg`，自动消失 3000ms，进入 120ms `--ease-emphasis`，退出 120ms `--ease-exit`，可堆叠最多 3 条（更早的向上挤压）
  - 允许的成功文案：「已发布 v27，3 项变更」「我的入口已导出到：D:\备份\我的入口-2026-09-29.json（共 14 项）」「入口已更新：2026 秋季报价模板」
- **文案禁令（不可违反）**
  - **写入本地待发队列不算成功**。`PENDING` 态只能用 `--warn-bg` + `clock` + 「反馈已保存，稍后自动发送」，**禁止**出现「已上报」「已发送给管理员」「反馈成功」等任何成功语义，`circle-check` 图标**不得**用于 `PENDING`。
  - 「重试」按钮按下但没成功时，不得先显示成功 Toast 再悄悄失败——成功态只能由真实的服务端确认产生。

### 4.6 失效反馈的投递三态（PENDING / SENT / DROPPED）

与 PRD §5.4.2 / 架构 T3.7 对齐。三态由投递结果决定，**UI 不得自行推导**：只有服务端确认接收后才是 `SENT`。

| 状态 | 含义 | 图标 | 配色 | 文案 | 持久化位置 |
|---|---|---|---|---|---|
| `PENDING` | 已写入本机待发队列，尚未送达 | `clock` | `--warn-bg` / `--warn-fg` | `反馈已保存，稍后自动发送` | 提交后的 Toast + 反馈入口旁的计数徽标 |
| `SENT` | **服务端确认接收**后才允许此态 | `circle-check` | `--success-bg` / `--success-fg` | `反馈已发送给管理员` | 提交后的 Toast（3000ms 自动消失） |
| `DROPPED` | 超出队列上限或保留期限，已丢弃 | `triangle-alert` | `--danger-bg` / `--danger-fg` | `这条反馈没能发送：{原因}。可以重新提交。` | **必须持久可见**，见下 |

**`DROPPED` 的四条硬要求（PRD AC-13a）**

1. **必须可见**：不允许静默消失，也不允许只写日志。至少在「更多菜单 → 失效反馈」入口上显示一枚 `triangle-alert` 徽标，打开后能看到被丢弃的条目。
2. **必须告知原因**：文案里必须出现具体原因，来自服务/队列给出的丢弃原因（超出队列上限 / 超过保留期限 / 内容不再有效），**不显示原始错误码**。例：`这条反馈没能发送：超过保留期限（7 天）未送达。可以重新提交。`
3. **必须给可重新提交的入口**：每条 `DROPPED` 项带一个「重新提交」按钮（secondary），点击后该项回到 `PENDING` 并重新入队，视觉立刻切回 `clock` + warn。
4. **不得冒充成功**：`DROPPED` 之后不得再显示该条为「已发送」；重新提交成功前不得出现 `circle-check`。

呈现规格：
- Toast：提交瞬间按当前态显示（§4.5 Toast 规格），`DROPPED` 的 Toast **不自动消失**（3000ms 改为常驻直到用户关闭或点「重新提交」）。
- 持久入口：更多菜单「失效反馈」项右侧显示最近态徽标 + 待发送/被丢弃计数（12px）。
- 无障碍：状态变化写入 `aria-live="polite"`；`DROPPED` 用 `role="alert"`。。
- Edge：
  - 名称 40 字上限（输入时限制）+ 卡片 2 行截断 + tooltip 全文
  - 路径超长：中间截断保留首尾 `D:\共享\…\2026 归档`
  - 分组 >8 或卡片 >200：发布前 **对话框内**提示「团队页已接近整理上限（8 组 / 200 项），建议先合并相似分组」，不阻断但需二次确认（PRD §13）
  - 重复目标：抽屉内黄色提示行，不阻断

## 5. 交互与动效规范

### 5.1 "操作流畅"的具体定义（可验证）

| 指标 | 目标 |
|---|---|
| 点击卡片到 OS 打开反馈 | 立即 (<80ms)，卡片按下态立即出现（不等子进程返回） |
| Ctrl+Space 到面板可见 | <80ms（预热窗口） |
| 搜索输入到结果更新 | <60ms，且**无动画**（动画在此会让人觉得卡） |
| 团队/个人 Tab 切换 | 160ms 内容切换 + 240ms 指示条移动，两者重叠发生 |
| hover 反馈延迟 | 0ms 开始，120ms 完成 |
| 60fps | 只允许 `transform` / `opacity` / `filter` 合成属性动画；禁止动画 `width/height/top/left/box-shadow`（阴影用两层伪元素 opacity 交叉淡入代替） |

### 5.2 关键交互动效表

| 交互 | 属性 | 时长 | 缓动 |
|---|---|---|---|
| 窗口首次显示（主窗口） | opacity 0→1 + scale 0.99→1 | 200ms | `--ease-emphasis` |
| Ctrl+Space 面板出现 | opacity + translateY(-4px→0) | 120ms | `--ease-emphasis` |
| 面板消失 | opacity + translateY(0→-4px) | 120ms | `--ease-exit` |
| 卡片 hover 抬起 | translateY(-1px) + 背景 + `--elev-2` | 160ms | `--ease-standard` |
| 卡片按下 | translateY(0) + 背景 active | 80ms | `--ease-standard` |
| 打开成功 | 图标容器 scale(0.96) 压一下即回原位（单向收敛，**非弹簧回弹**） | 120ms | `--ease-standard` |

| 下拉菜单展开 | opacity + scale(0.98→1)，transform-origin 顶部 | 160ms | `--ease-standard` |
| Tab 指示条移动 | translateX + width | 160ms | `--ease-standard` |
| Tab 内容切换 | opacity 淡入（旧内容同时淡出，交叉 80ms） | 160ms | `--ease-standard` |

| 骨架 shimmer | background-position | 1200ms infinite | linear |
| 加载 spinner | rotate | 1200ms infinite | linear |

**明确禁止出现在任何地方**
- `spring` / 回弹物理动画（linear→bounce 的二次运动）
- 数字滚动计数、confetti、礼花、进度条庆祝动画
- 每个 section 依次淡入的"页面级进场动画"（动效必须匹配它揭示的内容，而不是统一加戏）
- 打字机逐字输出效果（本项目无 AI 生成内容）
- 卡片轮播、自动播放、引导 highlighter 光斑

**焦点与导航实现要求**
- 卡片用 **roving tabindex**：整个网格只有一个 `tabindex="0"`，其余 `-1`；方向键移动焦点
- 所有看不到/不可达就没有意义的元素必须有 `:focus-visible` 双环
- Tab 顺序：标题栏按钮 → Tab 按钮 → 同步状态（可聚焦，Enter 触发刷新）→ 搜索 → 更多菜单 → 刷新 → 第一个聚焦卡片
- 焦点不被引用数据更新打断（PRD AC-08/09）
- `aria-live="polite"` 区域：同步状态变化、版本更新、编辑模式进入/退出
- `aria-live="assertive"` 区域：仅用于打开失败

### 5.4 鼠标 / 拖拽

- 双击卡片 = 打开（等同 Enter）；**（不提供双击重命名，右键菜单/更多菜单里走编辑）**
- 右键卡片 = 打开更多菜单（菜单项见 3.13）
- 编辑态拖拽排序：`grip-vertical` 手柄与整张卡片都可拖；拖起时原位置保留半透明占位（opacity 0.35，1px dashed `--border-strong`，这是虚线占位唯一合法用途）；其他卡片 160ms 让位
- 拖拽文件/文件夹/exe/快捷方式进入窗口 = 新建入口（支持三类的目标识别），拖入时整个窗口出现 2px `--accent` 内描边 + 顶部出现「松开以添加入口」提示条
- 从窗口往外拖出卡片到桌面 = 生成 Windows 快捷方式（P2，MVP 不做）

    --motion-instant: 0ms;

全部动效关闭后，仍有两个例外必须保留（无障碍要求：进行中的状态必须可感知）：
- 加载 spinner 与 shimmer：降级为静态 `--bg-surface-2` 块 + 文本状态（去掉 infinite）
- **离线状态点**：`opacity` 在 `1 → 0.45` 之间 2400ms **`ease-in-out`** 呼吸（不是已有并从属动效；这是唯一允许的常态动效，因为要表达"持续未同步"这个进行中的状态；reduced-motion 下改为静态 45% 透明度）

## 8. 无障碍（参照 PRD §14 可访问性 P1 + WCAG 2.1 AA）

### 8.1 对比度

已在 §2.6 标出关键文本对的实测值（均 ≥4.5:1，`--meta` 3.0:1 仅用于禁用与极次要，禁用于正文）。

实现期必须用 axe-core 或同类工具对以下组合做全量对比度校验：
- 文本 × 其背景（4 个 表面层级 × 3 个主题层级）
- 按钮文本 × 按钮背景（primary / secondary / ghost / destructive）
- 语义色 `-fg` × `-bg`（成功/警告/错误/信息 × 浅色/深色）
- 图标 × 容器（非文本元素 3:1）
- 焦点环 × 相邻表面（3:1）

### 8.2 不只靠颜色

| 信息 | 颜色之外通道 |
|---|---|
| 入口类型 | Lucide 图标形状 + 类型文字标签 + 副标签内容形态 |
| 来源（团队/个人） | 文字标签 + Tab 上下文 |
| 同步状态（8 态） | 四种点形态（空心 / 实心 / 旋转 / 呼吸）+ 6 个不同图标 + 各自不同的文案，见 §3.2.1 |
| 反馈投递（3 态） | 图标（`clock` / `circle-check` / `triangle-alert`）+ 各自文案 + 各自配色，见 §4.6 |
| 卡片失效 | `triangle-alert` 角标 + 副标签变文案 |
| 编辑模式 | 徽标文字 + 卡片句柄 + 底部操作条（4 重信号见 3.11） |

### 8.3 键盘与屏幕阅读器

- 全功能键盘可达（见 5.3）；无只靠 hover 才能触达的功能
- 每张卡片：`role="button"`（或原生 `<button>`）+ `aria-label` = `名称，类型，来源`（例：`2026 年度归档，文件夹，团队入口`）
- 更多的菜单按钮：`aria-haspopup="menu" aria-expanded`
- Tab：`role="tablist"` / `role="tab"` / `aria-selected` / `aria-controls`
- 图标按钮全部有 `aria-label`（必有文案：**无任何纯图标无标签按钮**）
- `aria-live` 区域见 5.3

### 8.4 系统环境

- Windows 125% / 150% 缩放下布局不得破（禁止固定 px 宽度的容器；所有宽度 Token 化）
- `@media (forced-colors: active)`：使用系统颜色（`Canvas` / `CanvasText` / `Highlight`），边框不消失
- `prefers-reduced-motion`：见 5.5
- 不使用需要 WebGL / GPU 特效才能表达的视觉信息

## 9. 前端实现指南

### 9.1 文件使用

```ts
// 全局一次性引入
import './design-system/design-tokens.css';
// 需要 JS 侧 Token 时（图表/动效脚本）
import tokens from './design-system/design-tokens.json';
```

主题切换：`<html data-theme="light|dark">`，切换时给 `<html>` 加 `.theme-transition` 类仅在需要过渡时使用，并在 160ms 后移除（避免全局 transition 拖慢后续重绘）。

### 9.2 已知坑（实现前必读）

| # | 坑 | 规避 |
|---|---|---|
| 1 | **滚动条吃掉宽度导致列数从 6 掉到 5** | 主窗口必须用 overlay 滚动条（见 3.1）。这是本项目最容易被忽略的视觉 bug。 |
| 2 | 深色模式下 `box-shadow` 几乎不可见 | 深色主题用表面亮度分级（`n-950 → n-900 → n-850`）+ 描边表达层级，阴影仅用于浮层。 |
| 3 | **Windows 上取不到 >32px 的软件图标**（`SHGetFileInfo` 上限，不是 bug） | 设计已按 32×32 定稿：不要浪费时间找"高清图标提取"方案或引入第三方图标提取依赖（多已停止维护）；取回的图 <24px 时不放大，直接回退 Lucide `AppWindow`。详见 §3.6。 |
| 4 | `-webkit-line-clamp: 2` 与 `display: grid` 冲突 | 卡片标题容器单独一层 `<div>` 承载 clamp，不要放在 grid item 本身。 |
| 5 | 焦点环被 `overflow: hidden` 裁剪 | 卡片不用 overflow hidden 或用 `outline` 而非 `box-shadow` 画焦点环。 |
| 6 | `transition: all` 会拖慢窗口级重绘 | 全部显式声明属性：`transition: background-color var(--motion-fast), transform var(--motion-base)`。 |
| 7 | Electron 首次 `show()` 白闪 | 窗口 `backgroundColor` 预置为 `--bg-canvas` 的十六进制值，并用 `ready-to-show` 事件后再显示。 |
| 8 | 中文与英文混排时视觉重量不一致 | 打包 Noto Sans SC 后 `font-display: swap`；若回退微软雅黑，务必把副标签从 12px 提到 13px 补偿可读性。 |
| 9 | `prefers-color-scheme` 与手动设置打架 | 手动设置为 `light` / `dark` 时不监听系统；仅 `system` 模式监听。 |
| 10 | 版本软更新时整页重绘 | diff 后仅对变化的卡片做 200ms 高亮；保留 Tab / 搜索词 / scrollTop。 |

## 10. Do's & Don'ts 与自检清单

### 10.1 禁止清单（出现即返工）

1. 禁止 emoji 作为任何功能、状态、类型图标
2. 禁止紫色 → 粉色渐变（`#7C3AED` `#A855F7` `#9333EA` `#EC4899` 之间任意组合）
3. 禁止"渐变 + 发光边框 + 毛玻璃"三位一体；本项目全站渐变使用量为 0
4. 禁止组件样式里出现硬编码色值（`#fff` `#000` 例外且不推荐使用）
5. 禁止首屏 Hero（大标题 + 空泛副标题 + CTA）。首屏就是卡片
6. 禁止 "Welcome to" / "Lorem ipsum" / "Sign up today" / "快速开始" / "一站式赋能" 类文案
7. 禁止弹性/回弹缓动，尤其是 `cubic-bezier(0.68, -0.55, 0.265, 1.55)`
8. 禁止 Tailwind 默认 Indigo `#6366F1` 作为强调色
9. 禁止卡片彩色左边框（`border-left > 1px`）
10. 禁止 `background-clip: text` 渐变文字
11. 禁止默认毛玻璃 / Mica / Acrylic
12. 禁止圆角 >16px
13. 禁止 `1px 边框` 与 `blur ≥16px 阴影` 同元素共存
14. 禁止每张 section 上方都放小型大写追踪标签（"ABOUT"/"PROCESS" 式 AI 语法）
15. 禁止 `01 · 关于 / 02 · 流程` 式编号小节标记
16. 禁止米色/奶油系背景（OKLCH L 0.84–0.97, C < 0.06, H 40–100）
17. 禁止虚构指标（"10000+ 团队信赖"）。要数字就用真实版本号、真实时间、真实计数
18. 禁止同时混合两套图标库（除已在 §6.1.1 登记、总量 ≤5 的 Tabler 例外）
19. 禁止任何图标字体、自绘 SVG 充当功能图标、emoji、第三方品牌 logo 集进入 UI（第三个来源一律不收）
20. 禁止为内置浏览器设计窗口 chrome / 前进后退 / 地址栏——MVP 网页入口一律交给系统默认浏览器
21. **禁止用布尔「在线 / 离线」表达同步状态**，必须实现 §3.2.1 的 8 态；状态只能由同步服务写入，UI 不得自行推导；「数据被拒」走状态键 `SYNC_DATA_REJECTED`，不得塞进 `offlineReason`
22. **禁止沿用上一轮的 `ONLINE_LATEST`**：新一轮轮询未成功完成必须退回 `SYNC_FAILED_UNKNOWN`
23. **禁止让 `OFFLINE_CACHED` 与 `OFFLINE_EMPTY` 共用一种空态**（由 `hasCache` 决定，UI 不得用"卡片数为 0"推断）
24. **禁止把原因扁平进状态枚举或用 UI 写死原因**：必须走「状态 + `offlineReason`」两段式；禁止把错误码 / 端口 / 堆栈显示给员工
25. **禁止把 `PENDING` 或 `DROPPED` 显示成已成功**：只有服务端确认接收才允许 `SENT`；`DROPPED` 不得静默消失，必须给原因 + 重新提交入口（PRD AC-13a）
26. **禁止把首次隐私说明做成可忽略的提示条**，也禁止只给一个按钮的假选择
27. 禁止 `云端` / `上云` / `云端分析` / `上传分析` / `数据资产` 等暗示数据出网的措辞

### 10.2 必须清单

1. 颜色 100% 走 Token
2. 间距 100% 是 4 的倍数（2px 例外仅用于图标光学对齐）
3. 图标统一 Lucide，尺寸 12/16/20/24 四档
4. 每屏 accent 填充 ≤2 处
5. 卡片标题最多 2 行 + tooltip 全文
6. 类型/来源/状态三重区分，颜色永远不是唯一通道
7. 覆盖 §3.7 的 8 类卡片状态与 §4 的 5 态
8. 支持 `prefers-reduced-motion` 与 `forced-colors`
9. 支持 125% / 150% 系统缩放不破版
10. 键盘可达全部功能，焦点可见（双环）
11. 同步状态实现 §3.2.1 的 8 态 + `offlineReason` 两段式，`ONLINE_LATEST` 不跨轮询沿用；四个 `offlineReason` 视觉权重一致，不得给罕见的 `CONNECTION_BLOCKED` 加事故级样式
12. `OFFLINE_CACHED` 与 `OFFLINE_EMPTY` 是两套行为，不共用空态
13. 反馈三态准确表达：`PENDING` 无成功语义，`SENT` 仅服务端确认后，`DROPPED` 可见 + 有原因 + 可重提
14. 首次隐私说明是不可跳过的状态门，未选择前零上报
15. 遥测开关在设置一级可见，关闭后停止记录 + 清空缓冲 + 不再请求
