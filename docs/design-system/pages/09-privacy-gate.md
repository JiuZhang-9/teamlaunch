# 页面设计提示词 · 隐私说明门（V-09）

> 触发：**首次启动**（遥测确认前）｜后续可从设置 →「查看隐私说明」再次打开
> 铁律：**未确认前不发送任何上报，也不得在磁盘上预缓冲**（AC-18）；内存暂存允许，落盘不允许
> 性质：这是一道**不可绕过的状态门**，不是可关闭的对话框

## 2. 组件组合（Spec §7 组件名）

```
PrivacyGate（状态门，非 Dialog）
├─ IconBox        [ShieldCheck 24]  ← 48×48 容器
├─ Text           标题「关于使用数据」
├─ Text           正文
├─ 要点块 ×4
│  ├─ MenuItem [CircleCheck 16] 只记录匿名设备标识与操作是否成功
│  ├─ MenuItem [CircleX 16]     不记录搜索内容、文件路径、网址
│  ├─ MenuItem [CircleX 16]     不记录你填写的说明与个人信息
│  └─ MenuItem [CircleX 16]     不用于任何个人绩效统计
├─ Text           补充说明
└─ 按钮组
   ├─ Button(secondary) 不允许
   └─ Button(primary)   允许并继续
```

**为什么用 `shield-check` 而不是锁**：这里是"说明 + 自主选择"，不是"需要授权"。用锁会暗示用户在被拦住，与"这道门是给你知情权"的语义相反。

## 3. 需要实现的全部状态

| # | 状态 | 触发 | 呈现 | AC |
|---|---|---|---|---|
| S1 | 首次门 | 首次启动且未确认 | 上述完整布局；**无 `X` 按钮、遮罩不可点、`Esc` 无效、窗口关闭按钮禁用** | AC-18 |
| S2 | 允许 | 点「允许并继续」 | 写入 `settings.json.telemetryEnabled=true` + `consentAt`；进入主窗口；遥测自此开始记录 | AC-18 |
| S3 | 不允许 | 点「不允许」 | 写入 `false` + `consentAt`；进入主窗口；**不写入任何 events 文件，不发任何请求** | AC-18 |
| S4 | 从设置查看 | 设置 →「查看隐私说明」 | 同一布局，底部按钮换成 `保持不允许` / `改为允许`（或反之，取决于当前值）；顶部追加一行 12px `--muted`：`当前：已允许` / `当前：不允许` | — |
| S5 | 设置里遥测开关（未确认） | 见 `07-settings-panel.md` S3 | 开关禁用 + 「查看隐私说明」按钮 | AC-18 |
| S6 | 首启事件补发 | 选了「允许」 | `clientId` 已在首启本地预生成并持久化；首启事件不单独上报，随**首次成功同步**的批量一起补发（C-02 裁定） | — |

**S1 的"不可绕过"是硬约束**：任何能跳过这道门进入主窗口的路径（拖窗口、按 Alt+F4 后重启、改配置文件）都等于违反 AC-18。未确认时主窗口 titlebar 的关闭按钮必须 `disabled`，Alt+F4 只退出应用不进入主窗口。

## 4. 真实中文文案

**标题**：`关于使用数据`

**正文**：`TeamLaunch 会记录少量匿名数据，用来判断哪些入口失效、需要修。上线前请确认：`

**要点四条**（第 1 条用 `circle-check`，后 3 条用 `circle-x`）
1. `只记录匿名设备标识与操作是否成功`
2. `不记录搜索内容、文件路径、网址`
3. `不记录你填写的说明与个人信息`
4. `不用于任何个人绩效统计`

**补充说明**：`数据保存在管理员电脑上，不经过外部服务器。可随时在「设置」里关闭。`

**按钮**：`不允许`（次级）/ `允许并继续`（主）

**从设置查看时的状态行**：`当前：已允许` / `当前：不允许`；按钮 `保持不允许` / `改为允许`

**禁用词（本行为清单原文，扫描豁免；出现即返工）**：`云端` `上云` `云端分析` `上传分析` `数据资产` `改善体验` `优化产品`；不得写"我们可能会…"这类模糊表述——四要点必须都是确定句

## 5. 键盘操作路径

| 按键 | 行为 |
|---|---|
| 打开 | **初始焦点落在「不允许」**（隐私默认取最小收集；视觉上「允许并继续」仍是主按钮） |
| `Tab` / `Shift+Tab` | 在「不允许」与「允许并继续」之间移动（仅 2 个 tab stop） |
| `Enter` / `Space` | 激活当前焦点按钮 |
| `Esc` | **无效**（不关闭、不跳过） |
| `Alt+F4` | 退出应用（不进入主窗口） |
| 点击遮罩 | **无效**（不关闭） |

- 门容器 `role="dialog"` `aria-modal="true"` `aria-labelledby`（标题）`aria-describedby`（正文）
- 未确认时主窗口其余部分 `aria-hidden="true"` 且 `inert`
- 选择后 `aria-live="polite"` 播报：`已允许使用数据统计` / `已关闭使用数据统计`

## 7. 实现红线（本页最容易做错）

1. **未确认前不得落盘任何事件缓冲**（AC-18）。内存暂存可以，`events/events.jsonl` 一个字节都不能写——写盘即视为已开始记录。
2. **这道门不能被任何方式绕过**：无 `X`、遮罩不响应、`Esc` 无效、窗口关闭按钮禁用、Alt+F4 只退出应用。任何一条漏了都等于违反 AC-18。
3. **初始焦点在「不允许」**。隐私默认应取最小收集；按 Enter 不应该在用户没读的情况下打开收集。
4. **两个按钮必须是平等的实体选择**，不能用"稍后再说""以后提醒我"这类第三选项拖延。
5. **四要点必须是确定句**，不能出现"可能""通常""一般不会"。
6. **禁用词零容忍（本行为清单原文，扫描豁免）**：`云端` / `上云` / `云端分析` / `上传分析` / `数据资产` 出现即返工。
7. **`clientId` 在首启本地预生成并持久化**（C-02），首启事件随首次成功同步补发——不要为了它单独改遥测数据结构，也不要在用户还没确认时就生成上报请求。
