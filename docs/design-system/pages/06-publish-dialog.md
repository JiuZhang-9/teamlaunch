# 页面设计提示词 · 发布对话框（V-06）

> 触发：EditActionBar「发布 · N 项改动」/ `Ctrl+Enter`｜写操作：`PUT /api/v1/config`
> 铁律：**先展示校验与变更摘要，确认后才真正发布**（AC-06）；校验失败必须阻止发布并定位问题项（AC-07）

| 校验结果块 | h 32，圆角 8，p-x 12，bg `--success-bg`，fg `--success-fg` | `--radius-md` |
| 变更块容器 | 圆角 8，1px `--border-subtle`，每行 h 32，p-x 12 | `--radius-md` |
| 变更行间距 | 行间 1px `--border-subtle` 分隔 | — |

## 3. 需要实现的全部状态

| # | 状态 | 触发 | 呈现 | AC |
|---|---|---|---|---|
| S1 | 校验通过 | 无问题项 | 绿色 StatusPill；发布按钮 enabled | AC-06 |
| S2 | 校验失败 | 空名称 / 非法 URL / 缺失目标 | 红色 StatusPill + 问题列表：**每项写明入口名 + 具体字段 + 原因**；发布按钮 **disabled**；每项右侧 `Crosshair` 16「定位」跳到该卡片并高亮 1.6s | AC-07 |
| S3 | 无改动 | 草稿为空 | 对话框不打开（EditActionBar 按钮本就 disabled） | — |
| S4 | 发布中 | 点击发布 | 按钮变 Loading（图标 `LoaderCircle` 20，**文案保持**）；对话框整体禁用但不关闭 | AC-06 |
| S5 | 版本冲突 | `ERR_REVISION_CONFLICT` | 校验区换成 warn 块：`团队数据已被更新到 v27，你的改动基于 v26` + 两个动作 `[重新拉取并合并]` `[取消]`；**不得自动覆盖** | AC-06 |
| S6 | 实例不匹配 | `ERR_INSTANCE_MISMATCH` | danger 块：`连的不是同一个团队数据源（instanceId 不一致）` + `查看诊断` | — |
| S7 | 签名失败 | `ERR_SIGNATURE_INVALID` | danger 块：`签名校验未通过，请重新启用管理员模式` + `去设置` | AC-16 |
| S8 | 超容量 | `ERR_PAYLOAD_TOO_LARGE` / 超 8 组 200 项 | danger 块：`配置超过上限（1MB / 8 组 / 200 项），请合并分组后再发布` | — |
| S9 | 限流 | `ERR_RATE_LIMITED` | warn 块：`操作太频繁，请稍后再试` | — |
| S10 | 发布成功 | 200 | 关闭对话框 + Toast「已发布 v27，3 项变更」；EditActionBar 回到「当前版本 v27」 | AC-06 |
| S11 | 网络不可达 | 请求发不出去 | danger 块：`发不到管理员电脑，改动仍保存在本机` + `[重试]` `[关闭]`；**草稿不得清空** | — |

**S5「重新拉取并合并」语义**：拉取服务端最新 revision，把本机草稿以**服务端为基**重新应用；无法自动合并的字段列出冲突项让管理员选。**绝不允许静默覆盖服务端新版本**。

## 4. 真实中文文案

**标题**：`发布到团队`

**版本行**：`v26 → v27`　`发布后在线成员将在 45 秒内更新`

**校验**
- 通过：`3 项改动全部通过校验`
- 失败：`2 项需要修正`
- 问题项：`报销单模板` — `目标路径为空，请选择本机上的文件夹`
- 问题项：`生产环境监控` — `htp:/ grafana.internal.company.com 不是有效的网址（示例：https://开头）`
- 定位按钮：`定位`

**变更摘要**：`新增 2 项` / `修改 1 项` / `删除 0 项`
展开明细示例：`+ 本周活动素材（文件夹）` `+ 季度 OKR 看板（网页）` `~ 2026 年度归档（文件夹）`

**发布说明 placeholder**：`例如：报价目录已迁移到新共享盘`

**按钮**：`取消` / `发布 · 3 项改动`（无改动时 `发布`，disabled）

**冲突与失败**
- 版本冲突：`团队数据已被更新到 v27，你的改动基于 v26` / `重新拉取并合并` / `取消`
- 实例不匹配：`连的不是同一个团队数据源（instanceId 不一致）` / `查看诊断`
- 签名失败：`签名校验未通过，请重新启用管理员模式` / `去设置`
- 超容量：`配置超过上限（1MB / 8 组 / 200 项），请合并分组后再发布`
- 限流：`操作太频繁，请稍后再试`
- 网络不可达：`发不到管理员电脑，改动仍保存在本机` / `重试` / `关闭`

**成功 Toast**：`已发布 v27，3 项变更`

**禁用词**：同全局；另禁止 `一键部署` `推送全员` `强制更新` `上线`（用"发布"）

## 5. 键盘操作路径

| 按键 | 行为 |
|---|---|
| 打开对话框 | 焦点自动落在**发布说明输入框**（不是发布按钮——避免连按 Enter 误发布） |
| `Tab` | 输入框 → 变更摘要可折叠项 → 取消 → 发布 |
| `Enter`（焦点在输入框） | **不发布**，什么都不做（单行输入）；要发布必须先 Tab 到按钮 |
| `Ctrl+Enter` | 发布（对话框打开时同样生效） |
| `Esc` | 关闭对话框，**草稿保留** |
| `Space`（焦点在折叠行） | 展开/收起该变更明细 |
| `Enter`（焦点在问题项「定位」） | 关闭对话框并跳到该卡片 |

- 对话框 `role="dialog"` `aria-modal="true"`，打开时主窗口 content 加 `aria-hidden`
- 校验失败时 `aria-live="assertive"` 播报：`2 项需要修正，发布已暂停`

## 7. 实现红线（本页最容易做错）

1. **打开对话框时焦点落在输入框而不是发布按钮**。默认聚焦发布按钮 + 管理员习惯性连按 Enter = 误发布。
2. **校验失败要定位到具体字段**，不能只说"有 2 项有问题"。`报销单模板：目标路径为空` 才是可用的报错。
3. **失败后草稿一律保留**（S5–S9 全部）。清空草稿是数据丢失事故。
4. **版本冲突不得自动覆盖**（S5）。服务端已有 v27 而本地基于 v26，静默覆盖会吞掉别人的发布。
5. **对话框宽度固定 480**。展开问题列表时不要变宽，按钮位置一动就会误点。
6. **发布成功后 revision 只增不减**（Spec §6 版本序列铁律）。回滚也必须新增 revision，客户端不需要任何"版本回退"分支。
7. **`Ctrl+Enter` 在对话框内与 EditActionBar 上行为一致**；不要在对话框里把它变成"换行"（单行输入不需要换行）。
