# 组件规格 · 管理员编辑态四重信号

> 唯一视觉契约 `docs/UIUX.md` §3.11 ｜ 页面用法见 `../pages/05-admin-edit.md`
> 目的：**管理员在任意滚动位置、任意注意力状态下，都能立刻知道自己正在改团队页且尚未发布**

---

## 为什么必须四重

管理员多为行政或 IT **兼职**，编辑团队页是低频动作（几周一次），期间会被打断。任何单一信号都会在某种场景下失效：

| 只看单一信号 | 失效场景 |
|---|---|
| 只有工具栏徽标 | 滚到页面中段，工具栏不在视野里 |
| 只有内容底色 | 深色主题下底色差异不明显，或被误认为"这个页面坏了" |
| 只有底部操作条 | 内容区滚动到底部时才有，且常与系统任务栏视觉混淆 |
| 只有卡片描边 | 与"选中态"难以区分，且空分组时完全没有卡片 |

**四重同时存在，任意一重进入视野即可确认状态。**

---

## 信号 1 — 内容区底色

| 属性 | 值 |
|---|---|
| 背景 | `--surface-editing`（浅色 `#F4F8FB` / 深色 `#151A1F`） |
| 与只读态对比 | 浅色下比 `--bg-canvas`（`#F7F8FA`）**更冷更暗一点**；深色下比 `--bg-canvas`（`#14171A`）**更亮一点** |
| 作用范围 | 整个 Content 区（含分组头之间的间隙），**不含** TitleBar / Toolbar / EditActionBar |
| 过渡 | 进入/退出编辑态时 160ms `--ease-standard` |

**不要做成"高亮黄"或"危险红"**。编辑态不是警告态，底色只承担"这里和平时不一样"这一个信息。

---

## 信号 2 — 工具栏徽标 + 编辑动作按钮

```
[PageTabs]  [● 编辑模式]  [↶ 撤销]  [+ 新建分组]  [+ 新建入口]
```

| 元素 | 尺寸 | 视觉 |
|---|---|---|
| StatusPill「编辑模式」 | h 24，p-x 8，圆角 pill，12 / 510 | bg `--draft-badge-bg`，fg `--accent-text`，前缀 `Pencil` 16 |
| 撤销 / 新建分组 / 新建入口 | h 28，p-x 8，图标 16 + 文字 12 | bg 透明，fg `--fg-2`，hover `--bg-surface-hover` |
| 与 PageTabs 间距 | 12 | `--space-3` |
| 按钮之间间距 | 4 | `--space-1` |

徽标是**唯一一处用 pill 圆角的控件**——它在工具栏里的辨识度来自形状而不是颜色。

---

## 信号 3 — 底部 EditActionBar

```
●  已编辑 3 项，尚未发布                    [放弃改动] [发布 · 3 项改动]
```

| 元素 | 尺寸 | 视觉 |
|---|---|---|
| 容器 | h 64，p-x 24，圆角**仅顶部** 12 | bg `--bg-overlay`，顶部 1px `--border-default`，`--elev-2` |
| 草稿点 | 8 × 8，实心 `--warn-solid`，呼吸 2400ms | 有改动时呼吸；无改动时隐藏 |
| 状态文案 | 14 / 510（`已编辑 3 项，尚未发布`）/ 14 / 400（`当前版本 v26`） | `--fg` / `--fg-2` |
| 放弃改动 | h 40，ghost | `--btn-ghost-*` |
| 发布按钮 | h 40，primary，`CloudUpload` 20 | 无改动时 **disabled 但保留可聚焦**（`aria-disabled`） |

**文案只有两种**：无改动写 `当前版本 v26`；有改动写 `已编辑 N 项，尚未发布`。不要写"草稿""未提交"这类内部术语。

---

## 信号 4 — 卡片级句柄与描边

| 元素 | 位置 | 尺寸 | 说明 |
|---|---|---|---|
| 边框 | 整卡 | 1px `--card-border-editing`（`--border-strong`） | **不用虚线**：125% / 150% 缩放下虚线会糊成锯齿 |
| 拖拽句柄 | 卡片**左上**角 | `GripVertical` 16，命中区 24 × 24 | **常驻显示**，不靠 hover——它是"这张卡能拖"的持续信号 |
| 编辑 | 卡片右上 | `Pencil` 16，命中区 24 × 24 | 常驻 |
| 删除 | 卡片右上（编辑右侧） | `Trash` 16，命中区 24 × 24 | 常驻，gap 4 |
| 分组头右侧 | 分组名右边 | `Plus` 16 / `EllipsisVertical` 16 | 「在此组添加」/「组操作」 |

**句柄放左上、操作放右上**：左上握持、右上操作，与 Windows 资源管理器的拖拽直觉一致；反过来会让鼠标行程跨越整张卡。

## 四重信号的降级（窄窗口 704px）

| 信号 | 704px 下的处理 |
|---|---|
| 1 底色 | 保留（唯一不占空间的信号） |
| 2 徽标 + 按钮 | 徽标保留；`新建分组` 收进 `EllipsisVertical` 菜单；`撤销` / `新建入口` 保留 |
| 3 底部操作条 | 保留，文案缩短为 `3 项未发布` |
| 4 卡片级 | 保留（这是卡片自己的属性） |

## 无障碍

| 项 | 规则 |
|---|---|
| 进入编辑态 | `aria-live="assertive"` 播报：`已进入编辑模式，改动发布后才会同步给团队` |
| 徽标 | `role="status"`，文本「编辑模式」直接可读，不依赖图标 |
| 发布按钮 disabled | 用 `aria-disabled="true"` + 保留 `tabindex="0"`，**不要用原生 `disabled`**（键盘用户会直接跳过，永远不知道为什么按不动） |
| 退出编辑态 | 播报：`已退出编辑模式` |
| forced-colors | 底色失效，改由徽标文字 + 底部操作条 + 卡片描边（`CanvasText`）承担 |

## 状态清单（编辑态自身的 5 态）

| # | 状态 | 四重信号表现 |
|---|---|---|
| 1 | 刚进入（无改动） | 四重信号全在；草稿点隐藏；发布按钮 disabled；文案 `当前版本 v26` |
| 2 | 有改动 | 草稿点呼吸；文案 `已编辑 3 项，尚未发布`；发布按钮 enabled `发布 · 3 项改动` |
| 3 | 发布中 | 四重信号保持；发布按钮 Loading（图标换 `LoaderCircle` 20，**文案保持**）；编辑区禁用但**草稿不清空** |
| 4 | 发布成功 | Toast `已发布 v27，3 项变更`；草稿点消失；文案回到 `当前版本 v27` |
| 5 | 发布失败 | 四重信号保持；**草稿必须原样还在**；Toast 或对话框给出可行动原因 |

## 实现红线

1. **四重信号缺一不可**。只做徽标是最常见的偷懒，也最容易被投诉"我不知道我改没改"。
2. **发布中不清空草稿**。只有服务端返回 200 才清；一次网络抖动丢掉十分钟编辑是最难挽回的事故。
3. **发布按钮 disabled 时仍要可聚焦**并带 `aria-disabled`。原生 `disabled` 会让键盘用户按 Tab 跳过。
4. **卡片描边不用虚线**。缩放下会糊。
5. **句柄常驻，不靠 hover**。hover 才出现的句柄在触屏和低注意力场景下等于不存在。
6. **16px 图标命中区 24 × 24**。三个图标挤在右上角，命中区小会互相误触。
7. **编辑态不是警告态**：底色、徽标都用中性/强调色，**不要套用 danger 配色**。
