# 组件规格 · SyncIndicator（8 态）

> 唯一视觉契约 `docs/UIUX.md` §3.2.1 ｜ 状态枚举由**同步服务**定义（架构 v1.4 T3.6 / T3.6.1），本文档只做「枚举 → 视觉」映射
> 本文档是**只读映射表**。UI 不得自行推导状态，不得自造状态

**v1.1 变更**：`offlineReason` 键名替换为架构正式枚举（4 值）；「返回数据校验失败」从**原因表**移入**状态表**，成为独立状态 `SYNC_DATA_REJECTED`（7 态 → **8 态**）；原因表按架构给出的真实频率重排。

---

## 0. 四条不可违反的规则

1. **状态只能由同步服务写入，UI 不得自行推导。**
   不得因为 `fetch` 抛错就判定为离线；不得用本地时钟判断版本先后；不得沿用上一轮状态。
2. **「已同步」只在当前轮询周期内有效。**
   进入下一轮轮询后，上一轮的 `ONLINE_LATEST` 必须失效；不得出现"刷新按钮点了但状态没变，界面还写着已同步"。
3. **`offlineReason` 是独立字段，不得扁平化进枚举。**
   同一个 `OFFLINE_CACHED` 可以有四种不同原因；原因决定第二行文案与下一步动作。
4. **「数据被拒」是状态，不是离线原因。**
   `SYNC_DATA_REJECTED` 那一刻**服务是连通的**，只是服务端拒了脏数据、保留了旧缓存。把它塞进离线语义会让用户看到"网络不可达"而实际上网是好的——这是误导，不是措辞问题。按**状态键**取这一行，不要按原因键。

## 1. 组件构成与尺寸

```

              管理员电脑未开机或未连接网络。…   11 / 400，行高 16   ← 第二行（仅 4 个态显示）
```

| 项 | 值 | Token |
|---|---|---|

## 2. 八态映射表

| # | 枚举 | 图标 16 | 活跃点 | 主色 | 第一行文案 | 第二行 | 刷新按钮 |
|---|---|---|---|---|---|---|---|
| 1 | `NEVER_SYNCED` | `cloud-off` | **空心**（1.5px 描边，无填充） | `--sync-fg-neutral` | `尚未获取团队入口` | 无 | 可用 |
| 2 | `SYNCING` | `loader-circle`（旋转） | 实心 · **呼吸** | `--sync-fg-busy` | `正在同步…` | 无 | 禁用（旋转中） |
| 3 | `ONLINE_LATEST` | `cloud` | 实心 · **静态** | `--sync-fg-ok` | `已同步 · 今天 09:12` | 无 | 可用 |
| 4 | `ONLINE_UPDATE_PENDING` | `refresh-cw` | 实心 · **呼吸** | `--sync-fg-busy` | `正在应用更新 v27…` | 无 | 禁用 |
| 5 | `OFFLINE_CACHED` | `cloud-off` | 实心 · **呼吸** | `--sync-fg-warn` | `离线 · 数据时间 今天 09:12` | **有**（`offlineReason`） | 可用 |
| 6 | `OFFLINE_EMPTY` | `cloud-off` | 实心 · **呼吸** | `--sync-fg-warn` | `暂时无法获取团队入口` | **有**（`offlineReason`） | 可用 |
| 7 | **`SYNC_DATA_REJECTED`** | `triangle-alert` | 实心 · **呼吸** | `--sync-fg-warn` | `更新未完成 · 仍使用今天 09:12 的数据` | **有**（固定，不走 `offlineReason`） | 可用 |
| 8 | `SYNC_FAILED_UNKNOWN` | `circle-x` | 实心 · **呼吸** | `--sync-fg-danger` | `同步未完成 · 数据时间 今天 09:12` | **有**（`offlineReason`） | 可用 |

**跨日格式**：`离线 · 数据时间 9 月 28 日 18:40`（当天用 `今天 HH:mm`，隔日用 `M 月 D 日 HH:mm`，隔年用 `YYYY 年 M 月 D 日 HH:mm`）。

**5 与 6 的强制差异**（这两个态表现必须不同，不得合并成一个"离线"）：
- `OFFLINE_CACHED`：**有缓存**，卡片照常渲染、照常可点，第二行写原因
- `OFFLINE_EMPTY`：**没有缓存**，内容区走空状态（`EmptyBlock`），第二行写原因 + 引导到「我的入口」

**7 与 8 的强制差异**：
- `SYNC_DATA_REJECTED`：服务**连通**，收到了响应但三重校验失败，已保留旧缓存 → 第一行说"更新未完成"，第二行说"仍使用上一版本"
- `SYNC_FAILED_UNKNOWN`：本轮**没拿到可用结果**且无法归类 → 第一行说"同步未完成"，第二行由 `offlineReason` 决定

> `SYNC_DATA_REJECTED` 且 `hasCache=false` 时：内容区走空状态，第二行省略"仍使用上一版本"，改为 `返回数据校验失败。你可以手动刷新再试。`

## 3. `offlineReason` → 第二行文案

**架构正式枚举（v1.4 T3.6.1），4 值**。仅 `OFFLINE_CACHED` / `OFFLINE_EMPTY` / `SYNC_FAILED_UNKNOWN` 三态读取本字段，其余状态为 `null`。

**下表按架构给出的真实频率降序排列。**

| 序 | 枚举名 | 语义 / 判定依据 | 第二行文案 | 频率 |
|---|---|---|---|---|
| 1 | `SERVICE_NOT_FOUND` | 发现阶梯 L0→L3 **零应答** | `管理员电脑未开机或未连接网络。稍后会自动重试，你也可以手动刷新。` | **高频**（"管理员没开机"实际落在这里） |
| 2 | `NETWORK_UNREACHABLE` | 端点已知但网络层失败（`ECONNREFUSED` / `ETIMEDOUT` / `EHOSTUNREACH` / `ENETDOWN`） | `这台电脑连不上内网。检查网络后会自动重试，你也可以手动刷新。` | 中 |
| 3 | `UNKNOWN` | 未归类兜底（以上均不成立或异常未识别） | `暂时连不上管理员电脑，稍后会自动重试。你也可以先使用我的入口。` | 兜底 |
| 4 | `CONNECTION_BLOCKED` | **UDP 信标有应答，但 TCP 连接失败** | `连接被安全软件或网络策略拦截。可手动刷新，仍不行请联系管理员或 IT。` | **罕见**（只在"信标通而 TCP 不通"这一窄条件下成立） |

### 3.1 视觉权重纪律（按频率，别让罕见分支抢戏）

四个原因的**视觉处理完全相同**：都是第二行 11px `--meta` 文案，都不改状态图标、都不改主色、都不加 danger 配色。频率排序的用处只有两条：

1. **不要在 `CONNECTION_BLOCKED` 上加"严重故障"级别的视觉处理**。它是最罕见的一支，却被写得像事故，会把用户注意力引到"是不是被监控了"上。
2. **不要把 `SERVICE_NOT_FOUND` 写得比 `UNKNOWN` 还轻**。它是最高频的一支（管理员关机、服务没起都落这里），文案必须给足下一步动作。

**技术上无法区分的情况不许硬编文案**：`NETWORK_UNREACHABLE` 无法区分"管理员机器已关机"与"中间件拦截"，所以这一支的文案**只说本机侧的网络状态**（`这台电脑连不上内网`），不许猜成"管理员关机了"。只有信标 UDP 通而 TCP 不通时才允许说"被拦截"。

### 3.2 兜底与禁止项

- **未覆盖 / 未识别的原因一律回落 `UNKNOWN`**，UI 回退到兜底行
- **禁止显示原始错误码、堆栈、端口地址、IP**（含 `ECONNREFUSED` / `ETIMEDOUT` 这类英文码）。地址与端口只允许出现在诊断页（`../pages/10-diagnostics.md`）
- 第二行**必须自带下一步动作**（稍后自动重试 / 手动刷新 / 使用我的入口 / 联系管理员或 IT）

## 4. 两个必须区分的边界情况

| 情况 | 正确处理 | 错误处理（会造成误报） |
|---|---|---|
| **有缓存但配置里 0 个入口** | 走**正常空状态**：`团队入口还没有内容` / `管理员还没有发布任何入口。你可以先使用我的入口。`；SyncIndicator 显示 `ONLINE_LATEST` | 套用离线/故障样式 → "管理员没发内容"被误报成"网络坏了" |
| **从未成功同步 + 管理员不可达** | `OFFLINE_EMPTY` + 空状态 + 手动刷新按钮 + 「我的入口」入口（AC-11） | 显示空白页或只显示一个转圈 |

**`hasCache` 不得由 UI 推断**：它也是同步服务写入的字段。UI 不得用"本地文件存在"或"卡片数为 0"来判断有没有缓存。

| 项 | 规则 |
|---|---|
| `aria-live` | 容器 `aria-live="polite"`；**状态无变化时不播报**（AC-09） |
| `aria-label` | `{第一行}。{第二行}`，例：`离线，数据时间 今天 09:12。管理员电脑未开机或未连接网络。稍后会自动重试，你也可以手动刷新。` |
| `role` | `status` |
| 呼吸动画 | 实心点在 4 个非稳态下 `opacity 1 → .45 → 1`，`--motion-breathe` 2400ms，`--ease-standard`；带 `data-motion="loop"` |
| 旋转动画 | `loader-circle` 旋转 `--motion-loop` 1200ms `--ease-linear`；带 `data-motion="loop"` |
| **reduced-motion** | 呼吸与旋转**全部停止**（不是变慢）：呼吸点固定 `opacity 1`，`loader-circle` 换成静态 `Clock` 16。辨识改由文案承担 |
| **forced-colors** | 点形态失效时，仍可靠 16px 图标 + 文案区分；容器加 1px `CanvasText` 边框 |

## 7. 实现红线

1. **UI 不得自行推导状态**。这是头号红线：看到 `fetch` 抛错就写"离线"、看到本地 revision 大就不拉更新，都是伪造状态。
2. **`OFFLINE_CACHED` 与 `OFFLINE_EMPTY` 表现必须不同**。合并成一个"离线"会让有缓存的用户看到空页面。
3. **有缓存但 0 入口 ≠ 故障**。走正常空状态，这是最容易误报的一处。
4. **`OFFLINE_EMPTY` 的标题是「暂时无法获取团队入口」，不是「未找到同步服务」**。"服务"两个字会让员工理解成"公司把这个功能停了"。
5. **「数据被拒」必须走状态键 `SYNC_DATA_REJECTED`，不得塞进 `offlineReason`**。那一刻网是通的，写成"网络不可达"是误导。
6. **四个 `offlineReason` 的视觉权重必须一致**。不得给罕见的 `CONNECTION_BLOCKED` 加事故级样式，也不得把最高频的 `SERVICE_NOT_FOUND` 写得比兜底还轻。
7. **第二行必须自带下一步动作**。只写原因不写怎么办，等于把问题甩给用户。
8. **员工可见界面禁止端口 / IP / 英文错误码**。诊断页是唯一例外。
9. **无变化时不重绘、不播报**（AC-09）。轮询返回 304 就什么都不做，连 `setState` 都不要调。
10. **`已同步` 只在当前轮询周期有效**。新一轮轮询开始就必须失效。
